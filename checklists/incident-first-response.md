# Чек-лист: подозрение на взлом сервера

Цель первых минут — понять масштаб и **не уничтожить следы**. Это памятка для
первичного осмотра, а не замена процедуре реагирования на инциденты.

## Чего не делать

- Не перезагружать сервер: пропадёт содержимое памяти и `/tmp`.
- Не удалять подозрительные файлы и не убивать процессы до фиксации.
- Не менять пароли с этого же сервера: ввод может перехватываться.
- Не доверять выводу утилит безоговорочно: `ps`, `ls`, `ss` могут быть подменены.

## 1. Изолировать

- [ ] Сообщить ответственным, зафиксировать время начала
- [ ] Ограничить сеть на уровне облачной группы безопасности или коммутатора,
      оставив доступ только со своего адреса
- [ ] Если это ВМ — сделать снапшот диска и памяти

## 2. Кто сейчас в системе

```bash
w                                   # активные сессии
last -Fai | head -n 30              # последние входы с адресами
lastb -Fai | head -n 30             # неудачные попытки (нужен root)
journalctl -u ssh --since "-2 days" | grep -E 'Accepted|Failed'
```

## 3. Процессы

```bash
ps auxwf                                    # дерево процессов
ps -eo pid,ppid,user,lstart,cmd --sort=start_time | tail -n 30

# Процессы, чей исполняемый файл удалён с диска
ls -l /proc/*/exe 2>/dev/null | grep '(deleted)'

# Что именно запущено под подозрительным PID
ls -l /proc/<PID>/exe /proc/<PID>/cwd
tr '\0' ' ' < /proc/<PID>/cmdline; echo
tr '\0' '\n' < /proc/<PID>/environ
```

## 4. Сеть

```bash
ss -tulpn                 # кто слушает порты
ss -tnp state established # установленные соединения с процессами
ip -br addr; ip route
iptables-save; nft list ruleset
```

## 5. Закрепление в системе

```bash
# Планировщики
for u in $(cut -d: -f1 /etc/passwd); do crontab -l -u "$u" 2>/dev/null | sed "s/^/$u: /"; done
ls -la /etc/cron.* /etc/cron.d/ /var/spool/cron/
systemctl list-timers --all

# Автозапуск: недавно изменённые юниты
find /etc/systemd /usr/lib/systemd /run/systemd -name '*.service' -mtime -30 -ls
systemctl list-unit-files --state=enabled

# SSH-ключи всех пользователей
find / -xdev -name authorized_keys -exec ls -l {} \; -exec cat {} \; 2>/dev/null

# Новые учётные записи и права
awk -F: '$3 == 0 || $3 >= 1000 {print $1, $3, $7}' /etc/passwd
ls -la /etc/sudoers.d/

# Подгрузка библиотек во все процессы — в норме файл пуст или отсутствует
cat /etc/ld.so.preload
```

## 6. Файлы

```bash
# Изменено за последние 3 дня в системных каталогах
find /etc /usr/bin /usr/sbin /usr/local -xdev -type f -mtime -3 -ls

# Исполняемые файлы там, где их быть не должно
find /tmp /var/tmp /dev/shm -type f -perm /111 -ls

# Целостность файлов из пакетов (Debian/Ubuntu)
dpkg --verify | grep -v '^??5?????? c '
```

## 7. После осмотра

- [ ] Сохранить собранный вывод и логи вне сервера
- [ ] Считать скомпрометированными все секреты, которые были на сервере:
      ключи, токены, пароли баз данных — заменить их
- [ ] Сервер с подтверждённым root-доступом злоумышленника **переустановить**,
      а не «чистить»: гарантировать отсутствие закладок нельзя
- [ ] Найти точку входа до возврата в работу — иначе всё повторится
