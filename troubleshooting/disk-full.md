# «No space left on device»

## 1. Место или inodes?

```bash
df -h      # место
df -i      # inodes
```

Ошибка одна и та же, а причины разные. Если по `df -h` место есть, а `IUse%`
равен 100% — закончились inodes: где-то лежат миллионы мелких файлов.

## 2. Закончилось место

```bash
# -x не выходит за пределы файловой системы
du -xh --max-depth=1 / 2>/dev/null | sort -h | tail -n 15
du -xh --max-depth=1 /var | sort -h | tail
ncdu -x /                # интерактивно, если установлен
```

Обычные подозреваемые:

| Где | Что проверить | Как освободить |
|---|---|---|
| `/var/log` | разросшиеся логи | исправить logrotate; `truncate -s 0 file.log` |
| journald | `journalctl --disk-usage` | `journalctl --vacuum-size=500M` |
| apt | `du -sh /var/cache/apt` | `apt clean`, `apt autoremove --purge` |
| Docker | `docker system df` | `docker system prune` (осторожно с томами) |
| старые ядра | `dpkg -l 'linux-image-*'` | `apt autoremove --purge` |
| `/tmp`, `/var/tmp` | забытые файлы | удалить вручную |

> Лог работающего приложения очищают через `truncate -s 0`, а не `rm`:
> после `rm` процесс продолжит писать в удалённый файл, и место не освободится.

## 3. `du` и `df` показывают разное

`df` говорит, что диск полон, а `du` столько не находит. Две причины.

**Удалённые, но открытые файлы.** Место освобождается, только когда файл
закроет последний процесс:

```bash
lsof -nP +L1                     # файлы с числом ссылок 0
```

Решение — перезапустить процесс (`systemctl restart ...`) или, если
перезапуск невозможен, обнулить файл через его дескриптор:

```bash
: > /proc/<PID>/fd/<FD>
```

**Файлы под точкой монтирования.** Данные записали в каталог до того, как
в него смонтировали другой раздел; теперь они скрыты, но место занимают:

```bash
mount --bind / /mnt && du -xsh /mnt/var/lib/data; umount /mnt
```

## 4. Закончились inodes

```bash
# В каких каталогах больше всего файлов
find / -xdev -type f 2>/dev/null | cut -d/ -f1-4 | sort | uniq -c | sort -n | tail
```

Типичные источники: файлы сессий PHP, почтовая очередь, кеш приложения,
каталоги `node_modules`. Удалять сотни тысяч файлов лучше так:

```bash
find /path/to/cache -type f -mtime +7 -delete
```

(`rm /path/*` упадёт с «Argument list too long».)

## 5. Зарезервированные блоки

На ext4 по умолчанию 5% раздела зарезервировано для root. На большом
разделе с данными это десятки гигабайт:

```bash
tune2fs -l /dev/sdb1 | grep -i 'reserved block count'
tune2fs -m 1 /dev/sdb1     # оставить 1%
```

На корневом разделе резерв уменьшать не стоит: именно он позволяет войти
и починить систему, когда место закончилось.

## Чтобы не повторилось

- Мониторинг места **и** inodes с порогами
  ([disk-alert.sh](https://github.com/Elylya-hash/linux-admin-scripts/blob/main/scripts/disk-alert.sh)).
- Ротация для каждого лога, который пишет приложение.
- `SystemMaxUse=` в `journald.conf`.
- Отдельные разделы для `/var/log` и данных: переполнение не остановит систему.
