# Сеть: «не открывается» и «не подключается»

Идти снизу вверх по уровням и на каждом шаге отвечать на один вопрос.

## 1. Интерфейс и адрес

```bash
ip -br link          # состояние интерфейсов: UP / DOWN
ip -br addr          # адреса
ip -s link show eth0 # счётчики ошибок и отброшенных пакетов
```

## 2. Маршрут

```bash
ip route                     # есть ли маршрут по умолчанию
ip route get 8.8.8.8         # через какой интерфейс и шлюз пойдёт пакет
ping -c 3 <шлюз>
```

## 3. Доступность узла

```bash
ping -c 3 192.0.2.10
mtr -rwc 20 192.0.2.10       # потери и задержки по каждому узлу маршрута
```

Отсутствие ответа на ping ещё ничего не значит: ICMP часто закрыт. Потери на
промежуточном узле в `mtr` при нуле потерь на последнем — тоже норма
(маршрутизатор ограничивает ICMP-ответы).

## 4. DNS

```bash
dig +short example.com
dig example.com @1.1.1.1         # тот же запрос к другому серверу
resolvectl status                # какие серверы использует systemd-resolved
getent hosts example.com         # как имя видит система (учитывает /etc/hosts)
```

Если по IP работает, а по имени нет — проблема в DNS. `dig` обходит
`/etc/hosts` и `nsswitch.conf`, а `getent` показывает то, что получит приложение.

## 5. Порт

```bash
nc -vz 192.0.2.10 443                # TCP-порт
curl -v --connect-timeout 5 https://example.com/
```

Как читать результат:

| Результат | Что значит |
|---|---|
| `Connection refused` | узел доступен, но порт никто не слушает (или фаервол отвечает REJECT) |
| таймаут | пакеты отбрасываются: фаервол (DROP), группа безопасности, маршрут |
| `No route to host` | нет маршрута или ICMP-отказ от фаервола |
| соединение есть, ошибка TLS | сертификат, SNI, версия протокола |

## 6. На стороне сервера

```bash
ss -tlnp                         # слушает ли сервис и на каком адресе
```

`127.0.0.1:8080` — сервис доступен только локально. `0.0.0.0:8080` или
`*:8080` — на всех интерфейсах.

```bash
ufw status verbose               # или: nft list ruleset / iptables -S
curl -v http://127.0.0.1:8080/   # отвечает ли сервис локально
```

Если локально отвечает, а снаружи нет — фаервол на сервере, облачная группа
безопасности или сервис слушает не тот адрес.

## 7. Посмотреть пакеты

Когда неясно, доходят ли пакеты вообще:

```bash
tcpdump -ni any port 443 and host 203.0.113.5
```

- SYN приходит, ответа нет — пакет отбрасывает локальный фаервол или никто
  не слушает порт.
- SYN приходит, SYN-ACK уходит, а соединения нет — проблема на обратном пути
  (асимметричная маршрутизация, `rp_filter`).
- Ничего не приходит — проблема до сервера.

## TLS

```bash
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null |
    openssl x509 -noout -subject -issuer -dates
```

## Медленно, а не «не работает»

```bash
curl -o /dev/null -s -w 'dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} ttfb=%{time_starttransfer} total=%{time_total}\n' https://example.com/
```

По разнице между соседними значениями видно, на каком этапе теряется время:
разрешение имени, установка соединения, TLS или ответ приложения.
