# Высокая нагрузка: сервер «тормозит»

## Сначала — что именно загружено

```bash
uptime                 # load average за 1, 5 и 15 минут
nproc                  # с чем сравнивать
vmstat 1 5             # общая картина раз в секунду
```

Load average в Linux — это не только CPU: в него входят процессы, ожидающие
диск (состояние `D`). Поэтому высокий LA при простаивающем процессоре — это
почти всегда ввод-вывод.

Как читать `vmstat`:

| Столбец | Что значит | Когда плохо |
|---|---|---|
| `r` | процессы в очереди на CPU | стабильно больше числа ядер |
| `b` | процессы, заблокированные на I/O | больше 0 продолжительное время |
| `si` / `so` | подкачка с диска / на диск | любые ненулевые значения в динамике |
| `us` / `sy` | CPU в пользовательском коде / в ядре | `sy` выше 20–30% — много системных вызовов или прерываний |
| `wa` | ожидание I/O | больше 10–20% |
| `st` | время, отобранное гипервизором | больше 5–10% — «шумный сосед» |

## Ветка 1: CPU (`us`/`sy` высокие, `wa` низкий)

```bash
top -o %CPU                          # или htop
ps -eo pid,user,%cpu,etime,cmd --sort=-%cpu | head
pidstat -u 1 5                       # пакет sysstat: динамика по процессам
top -H -p <PID>                      # потоки внутри процесса
```

Что процесс делает прямо сейчас:

```bash
strace -c -p <PID>                   # статистика системных вызовов (Ctrl+C для итога)
perf top -p <PID>                    # горячие функции
```

## Ветка 2: диск (`wa` высокий, `b` > 0)

```bash
iostat -xz 1 5       # %util близко к 100 и растущий aqu-sz — диск не справляется
iotop -oPa           # кто пишет и читает
pidstat -d 1 5
```

Частые причины: бэкап или `updatedb` в рабочее время, база данных без
индексов, переполненный диск, подкачка (см. ниже).

## Ветка 3: память (`si`/`so` ненулевые)

```bash
free -h                              # смотреть на available, а не на free
ps -eo pid,user,rss,cmd --sort=-rss | head
journalctl -k --since "-1 day" | grep -iE 'out of memory|oom-kill'
```

Занятая кешем память (`buff/cache`) — это нормально: ядро отдаст её по первому
требованию. Проблема — когда мал `available` и активно используется swap.

Давление на ресурсы одним взглядом (ядро 4.20+):

```bash
cat /proc/pressure/cpu /proc/pressure/memory /proc/pressure/io
```

`some avg10=25.00` означает: за последние 10 секунд 25% времени хотя бы один
процесс ждал этот ресурс.

## Если непонятно, что было ночью

```bash
sar -q -f /var/log/sysstat/sa$(date -d yesterday +%d)   # load average
sar -u -f ...                                            # CPU
sar -r -f ...                                            # память
sar -d -f ...                                            # диски
```

`sysstat` нужно включить заранее (`systemctl enable --now sysstat`) — задним
числом история не появится.
